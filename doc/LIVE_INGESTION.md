# 实时摄取

完成一次本机历史读取后，可在 **数据与同步 → 实时摄取** 分别开启 QQ / 微信监听。新消息进入本地库后可被 Agent 检索，已打开的聊天浏览窗口也会刷新。

## 状态与范围

实时开关和历史导入勾选独立。界面区分客户端是否运行、监听是否启用、最近成功时间、新增数量及错误。程序退出后不继续监听。

显示更新完成只说明当前可读取的本地资料已处理，不表示服务器历史完整。失败不会推进对应进度；本地缓存、账号、密钥或文件发生变化时可能需要手动补读。

## 实现

- 使用现有进程机制、SQLite 持久游标、原生消息身份和去重；QQ / 微信分别运行。
- QQ 使用经过版本与页校验的专用 SQLite / VFS 兼容路径，处理 Windows 特殊锁页；不会将该行为扩散到主库或微信。
- 微信实时路径复用已验证的缓存密钥，避免每轮扫描整个客户端内存。缺失新的库密钥时明确报错，手动历史读取后可以恢复。
- 媒体按消息定位，进行有限的延迟重试。图片不可用不阻塞文字入库；表情默认关闭，可手动指定范围刷新。
- 时间戳用于显示和访问范围，不作为工作区统一变化流的唯一游标。

工作区另外通过本地持久递增序列发现消息、转写、文件解析等有效变化。读取资料和生成草稿不会触发自身循环更新；见 [WORKSPACES.md](WORKSPACES.md)。

验证使用 `check_live.py`、`check_live_runtime.py`、`check_snapshot_recovery.py` 等隔离夹具。真实客户端到达延迟和兼容性必须在目标机器另行检查，不能由夹具推断。
