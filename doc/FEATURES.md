# Tulpa 功能说明

更新日期：2026-09-26。本文按当前开发源码说明已有功能、使用条件和限制，不列入尚未实现的计划。

Tulpa 是 Windows 桌面应用，支持导入和查询 QQ / 微信聊天、理解消息中的图片与语音、整理文件和证据、生成回复草稿，以及通过关注卡和工作区持续处理指定主题。

## 1. 运行与配置

- 桌面版完整解压后运行 `Tulpa.exe`，运行所需模块随包提供；保留浏览器入口供开发和测试。
- 面向 Windows 10 / 11 x64。QQ、微信客户端需要单独安装和登录；读取能力受客户端版本、本机缓存和进程权限影响。
- 用户在产品内填写模型 API 地址、API Key 和模型名称。当前使用现有 Harness 执行模型与工具调用，已实际验证 DeepSeek；其他兼容接口需要支持相应流式请求和工具调用，不能保证所有供应商均可直接使用。
- 使用默认系统字体、暖色浅色界面；侧栏提供普通对话、聊天记录、文件 / 资料、证据集合、关注卡、工作区和记忆入口。
- 数据与配置保存在本机程序目录。移动或备份时应保留完整目录，不能只移动 EXE。
- 程序退出后，实时读取和定时任务停止执行。

## 2. 聊天数据导入与同步

### 历史导入

- 从本机已登录的 QQ / 微信读取当前客户端保存的聊天。
- 两个平台可以分别选择会话、开始日期、截止日期和读取数量。
- 支持一次读取所选日期范围内全部消息，由程序自动分批处理；主界面批量入口没有原来的 50,000 条整轮截止。
- 显示读取阶段、进度条、扫描数量、新增 / 已有 / 跳过数量、已提交批次、耗时和诊断编号。总量未知时显示活动状态，不显示估算百分比。
- 支持停止导入；已提交数据保留。按相同设置重试可接续已完成批次，必要时重新扫描并去重。
- 支持 JSON / JSONL 导出文件导入，包括 QCE、wx-cli、ChatLab、WeFlow 及项目统一格式。文件导入只处理文件已有内容，不补读客户端历史；单文件上限 100 MB。

### 实时读取与刷新

- QQ / 微信分别开启实时读取，新消息自动进入本地数据库，随后可供 Agent 检索。
- 实时开关与某次历史导入的平台、会话、日期设置独立。
- 支持手动刷新新增消息，也可设置仅同步数据的定时刷新；这类刷新本身不调用模型。
- 界面分别显示平台读取状态、最近成功时间、新增数量和错误。
- 失败不推进相应读取进度，重新启动后可接续已有进度。客户端清理数据、账号变化或缺少密钥等情况可能需要补读或修复进度。

### 图片和表情恢复

- 普通图片与表情包分别处理，表情包默认不读取。
- 历史导入、实时读取、自动刷新及关注卡各自保留相应表情设置。
- 可以指定平台、会话和日期，刷新已入库消息的图片 / 表情，恢复本机后来可用的资源。
- 对近期实时入库但媒体缺失的消息进行有限重试；超过范围或定位信息不足时，由用户手动补读或刷新。

读取只覆盖本机或导出文件中实际存在、当前读取器能够解析的内容，不等于下载 QQ / 微信服务器上的全部历史。

## 3. 原始聊天浏览

- 左侧按群聊或私聊选择会话，支持搜索名称；会话卡显示最后一条消息预览和时间。
- 右侧显示原始聊天、发送者、时间、引用回复及可用媒体。
- 打开聊天窗口期间会更新新入库消息，无需重新打开窗口；阅读较早记录时可以返回最新位置。
- 支持向前 / 向后查看消息，并从 Agent 引用定位到指定消息及附近上下文。
- 消息可保存到证据集合，也可直接触发“帮我回复”。
- 原始记录区域用于浏览，不提供任意编辑原始聊天的功能。

界面的实时更新以消息已经进入 Tulpa 本地数据库为前提，不代表客户端读取始终无延迟或无遗漏。

## 4. Agent 查询与分析

- 用自然语言查询聊天，定位联系人、群聊、某段时间或某个主题。
- 支持多轮追问，保存对话历史、查询过程和使用情况。
- Agent 可自主搜索消息、展开前后文、分页阅读、补搜相关内容，再组织回答。
- 支持按稳定账号查询人物及同平台不同会话中的名称；相同昵称不会自动视为同一个人，也不自动跨平台合并身份。
- 支持寻找可能提及本人的消息、梳理多人互动、提取通知与时间安排、统计指定范围内的消息。
- 可执行受限只读 SQL 完成统计；SQL 同样遵守用户允许的平台、会话和日期范围。
- 提供快速、标准、深入、充分四档分析强度，共享整轮模型请求、工具调用、消息、证据字符和时间预算。
- 显示真实工具进度，支持停止回答；已取得的过程和对话记录保留。
- 可展开引用查看原文、文件片段及相关上下文。

普通聊天会直接展示模型输出；未通过格式或引用检查的段落在下方标注原因，不再折叠隐藏。显示出来不代表已经核实，未读过的引用不会被包装成有效原文链接。

输入框下方的“显示思考过程”默认开启，可关闭。它显示模型接口实际返回的思考内容，与最终回答分开；没有返回该字段时不显示。开关只控制展示，不改变分析强度，也不把思考内容作为事实证据。

## 5. 图片、语音与文件理解

| 资料类型 | 可用功能 | 主要条件与限制 |
| --- | --- | --- |
| 普通图片、可恢复表情 | 预览；按需进行本地 OCR 或模型原生识图 | 本地资源需可获取；原生识图会将所选图片发送给配置的模型服务 |
| 原生语音 | 准备播放、本地转写、失败重试；转写后搜索并引用原消息 | 原始音频需可获取；转写可能误听，保留机器转写标识 |
| PDF、DOCX、PPTX、XLSX | 按需解析、检索正文、读取片段并引用 | 以解析器实际提取到的文本为准，不保证扫描件、复杂版式或嵌入图片均可理解 |
| 文本、Markdown、CSV、JSON、代码及日志等文件 | 读取、分段检索和引用 | 受支持扩展名、文件大小、解析时间和任务预算限制 |
| 视频 | 可保留消息或文件信息 | 尚不支持视频内容理解 |

语音默认按需转写，也可选择新语音后台转写或指定历史补转写。原始音频在本机处理，必要的转写文字可随查询发送给模型。

文件消息先登记名称、来源和可用性；用户或 Agent 需要正文时才取得和解析文件，不默认下载、解析全部附件。没有落盘、已经过期或被删除的附件可能无法取得。

## 6. 文件资料库与证据集合

### 文件 / 资料

- 汇集 QQ / 微信文件消息与已启用的 QQ 群文件目录。
- 按名称、来源、会话等条件查找文件，并检索已经解析的正文。
- 查看文件来源、可用状态和正文片段，跳回相关消息。
- 相同内容可以复用解析缓存，同时保留不同来源及各自访问范围。

### 证据集合

- 将消息、图片、语音、文件片段及可用的 QQ 群资料保存为引用集合。
- 支持新建、命名、添加、移除、查看来源和删除集合。
- 保存引用不会复制整个聊天库；删除集合不会删除原始聊天或文件。
- 聊天原文、文件原文、机器转写、图像识别、SQL 统计和用户补充分别保留来源性质。

## 7. 帮我回复

### 生成与编辑

1. 在真实聊天消息上右键或点击“帮我回复”。
2. 当前聊天底部展开回复面板，填写可选要求，并选择分析强度与识图方式。
3. 点击生成后，同一输入框显示可编辑的回复草稿。
4. 可以调整要求、重新生成、编辑、复制、停止生成，并查看本轮实际读取的上下文、耗时和用量。

回复依据包括目标消息、附近上下文、当前会话中的本人表达样本，以及检索到的相似真实互动。模型输出纯文本草稿，不要求它返回证据编号；程序单独记录实际读取的来源。

历史互动可以直接从已导入聊天中检索，不需要先积累 Tulpa 成长进度，也不需要先导入派生记忆库。每轮优先选择同会话、同一个人及相似场景，最多参考 8 个互动案例；没有可靠回复关系时不会强行凑足案例。

### 审批与发送

- 面板底部提供“批准”和“拒绝”。批准发送当前编辑框中的准确文字；拒绝不会发送。
- QQ 好友私聊和群聊支持文本发送，需要有效的本机 OneBot 接口。
- 引用原消息需底层接口支持且能够唯一核对原消息；无法核对时不能直接发送带引用的回复。
- 微信目前支持草稿、编辑和复制，不支持发送。
- 保留 AI 原稿、用户修改、生成历史、审批状态和发送结果。
- 发送结果未知时不自动重发，避免重复消息。

模型本身没有发送权限。草稿仍可能误判语气、关系或用户意愿；批准前可自行修改。协议发送成功后，手机与桌面 QQ 的显示可能不同，Tulpa 将发送回执与原始聊天分开展示。

## 8. Tulpa 行为记忆

- 按群聊或私聊分别维护自动记忆、人工修正、成长计数和真实互动案例。
- 默认开启，可用 ON / OFF 控制；查看记忆不会触发模型整理。
- 历史导入属于已有档案，不因导入大量历史而自动生成全部人物或群聊记忆。
- 开启之后的新有效文字按范围积累：群聊计算本人文字；私聊计算双方文字，且整理阶段需有本人参与。
- 每累计 100 条符合条件的文字进行一次有限模型整理。纯表情、图片、语音、文件和系统占位不计入该门槛。
- 人工修正独立保存，不被自动整理覆盖。
- 关闭后停止新成长及成长记忆注入；已有记忆保留，消息同步和历史回复案例检索继续可用。
- 相关原文删除或发生有效修改后，受影响的自动记忆与案例会停用。

当前成长记忆主要用于“帮我回复”。普通查询聊天不会自动注入这套群聊 / 好友成长记忆，但仍可通过原始聊天查询人物和互动。派生记忆是可修订判断，不是新的原始事实来源。

## 9. 关注卡

- 保存一个长期关注的问题，并限定平台和会话。
- 可从普通回答或原始消息创建，也可直接新建。
- 手动检查或到期时，使用普通 Agent 的检索工具与预算重新询问该问题；优先查近期变化，必要时回查旧证据。
- 支持按时间自动检查、累计指定数量的新消息后检查，或同时开启两种条件；同时开启时任一条件满足即触发。
- 在卡片内继续追问，查看历次回答、来源、耗时和用量。
- 支持修改设置、暂停 / 恢复、停止当前检查和删除卡片。
- 失败或取消后保留上一次成功回答，不把失败任务当作已更新。

消息数量用于触发检查，不表示要求逐条读完，也不表示所有记录已经检查。卡片的查询范围与单次导入选择独立；客户端刷新失败时仍可查询本地资料，并提示数据状态。

## 10. 工作区 Workspace

### 持续任务与资料组织

- 以目标创建工作区，设置允许访问的平台、会话和时间范围。
- 可从已有消息、文件或证据集合开始，不改变原共享集合。
- 工作区以连续 Agent 对话为主，资源树包含当前状态、成果、资料、证据、笔记和历史版本。
- 多次任务共用资料与成果；后续任务可读取并修改同一份文档。
- 资料显示来源、关联原因和确认状态；移除 / 排除决定保留，不因再次扫描自动加回。
- 可以关联已有关注卡；关注卡仍使用自身的设置与调度。

### 成果与版本

- 创建、预览、编辑和下载 Markdown 报告及 CSV 索引。
- 当前状态也是受版本管理的文档，可保存已确认事实、重要背景、近期变化和待确认事项。
- 普通提问只读；整理任务和用户补充形成修改建议，不因一次回答自动更新正式状态。
- 正式修改先提出提案，用户查看差异并确认后才应用，包括新成果、修改成果和资料关联。
- 支持批量应用 / 忽略建议、查看历史版本和恢复旧版本。
- 手工编辑和任务修改检查基础版本，旧任务不能覆盖较新的编辑。
- 用户补充单独标注，不冒充已经从聊天中查证的事实。

### 增量维护

- 跟踪本地消息新增 / 修改 / 删除、媒体恢复、语音转写变化、文件来源与解析变化，以及已同步的 QQ 群资料变化。
- 区分数据进入本地、候选已处理和修改已应用。
- 默认先发现候选，由用户点击“整理最近变化”或发任务进行分析。
- 可开启每天、每周或自定义频率的维护，并指定预算；默认关闭。
- 没有待处理候选时不调用模型；有候选时也只产生修改建议，不自动应用正式成果。
- 支持指定日期补查；任务失败、取消或预算耗尽时保留草稿及待处理内容。
- 缩小访问范围后，旧任务和旧成果不能用于绕过新范围。

工作区维护只跟踪已经进入本地的变化，不代表 QQ / 微信服务器资料已经完整同步。删除工作区不删除原始消息、共享集合或独立关注卡。

## 11. QQ 群管理

配置有效 OneBot 后，可在普通聊天中用自然语言提出以下操作：

- 查看群信息、成员和待处理入群申请。
- 同意或拒绝直接入群申请。
- 禁言、解除禁言、移出成员。
- 修改群名称。

程序在提案与执行前核对当前 QQ 账号、目标群、成员及权限。可执行范围取决于实际群角色和接口支持。

输入框上方显示具体操作卡，包含目标、时长或新名称，并提供“允许 / 拒绝”。每个普通对话可以单独设置审批方式：

| 审批方式 | 行为 |
| --- | --- |
| 每次询问，默认 | 等待用户对具体操作允许或拒绝 |
| 默认允许 | 对之后的新任务，执行通过权限检查的具体操作并记录结果 |
| 默认拒绝 | 保留提案记录，但拒绝执行 |

切换设置不会自动批准已有待审批项。群管理写操作目前仅接入普通聊天，不在关注卡、工作区或回复助手后台执行。“默认允许”也不会开启监听消息后的自动管理。

## 12. QQ 公告、精华和群文件

公告、精华、群文件目录与 QQ 发送共用产品内配置的本机 OneBot 地址和 Token。QQ 和接入程序需保持运行；未配置或连接无效时，不向模型提供这些实时读取工具。

- 按需读取群公告和精华正文，保留其独立来源；加精时间不当作原消息发送时间。
- 查询群文件目录、名称、上传信息和可用状态。
- 对需要的文件申请下载地址、下载、解析并读取片段，不默认下载整群文件。
- 本地已存在的附件与解析缓存仍可独立使用。

### 不同入口的支持情况

| 能力 | 普通聊天 | 关注卡 | 工作区 |
| --- | --- | --- | --- |
| 按需读取公告、精华 | 支持 | 检查 / 追问时可使用 | 任务中可使用 |
| 查询群文件目录、按需下载并读取 | 支持 | 支持 | 支持 |
| 使用资料形成回答 | 支持 | 支持 | 支持，也可提出成果及资料关联建议 |
| 群管理写操作及审批卡 | 支持 | 未接入 | 未接入 |
| 未通过检查的回答直接展示 | 已接入 | 仍沿用原检查方式 | 仍沿用原检查方式，正式成果保留校验 |

上述读取仍受各入口的平台、会话和日期范围限制。相关群需有已导入记录，并且当前 OneBot 账号与来源账号一致。

### 自动更新的现有边界

- 按需工具可用，不代表每轮 Agent 都会查询全部群资料；任务需要涉及相应来源。
- 关注卡按消息数量触发时只计算聊天记录，单独新增公告、精华或文件不计入该消息数量。
- 工作区先查看本地变化；远端新增资料需先经资料同步或按需读取进入本地，才能作为工作区候选。
- 已启用的公告 / 精华周期同步与群文件目录同步有独立周期，不是实时监听全部群资料。
- 配置 OneBot 本身不会自动启用所有群的资料同步。

## 13. 数据管理与诊断

- 按平台、会话和日期管理已导入数据，支持范围删除及相关缓存清理。
- 删除前显示范围并要求确认，不修改 QQ / 微信客户端的原始数据库。
- 历史导出文件、备份、报告和旧 AI 回答可能仍保留相关内容；删除本地消息不等于彻底擦除全部私人数据。
- 查看导入、实时读取和同步的阶段、数量、耗时及错误状态。
- 生成诊断摘要，包含系统、运行时、客户端版本、权限和错误类别。
- 提供十分钟有效的临时只读诊断连接；只暴露诊断摘要，不能远程执行命令、浏览文件或读取聊天。
- 后台保留结构化诊断日志，便于按任务编号排查问题。

## 14. 数据与操作边界

- 聊天、媒体、工作区、记忆和配置保存在本机；使用云端模型时，任务所需的有限文本或选择上传的图片会发送给用户配置的模型服务。
- API Key 和 OneBot Token 不随公开源码或发布包分发。用户配置保存在本机文件中，不是加密保险库。
- 原始 QQ / 微信数据库通过读取器只读访问；QQ 发送和群管理通过独立接口执行。
- Agent 没有开放 Shell 或任意本地文件访问权限；工具执行用户设置的数据范围及预算。
- 目前没有微信发送、无人审批的回复机器人、视频理解、全库自动人格训练或任意电脑远程控制。
- 当前仍是预览版本。不同客户端版本、权限、缓存状态和模型接口的兼容性需分别验证；有工具或接口不代表所有分支都经过真实环境验收。
