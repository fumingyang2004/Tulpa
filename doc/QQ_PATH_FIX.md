# Tulpa 0.5.1：QQ 读取临时修复包 v2

适用于 QQ 已登录，但 Tulpa 的账号列表为空，聊天保存位置使用了自定义目录的情况。支持 0.5.1 完整版和 MCP 版。

本次修复包默认读取 **`F:\QQ\缓存`**。它将聊天记录导入到你正在使用的 Tulpa，不会搬走 QQ 的原始文件，也不需要安装另一个 Tulpa。

v2 同时修复被动密钥扫描的性能和日志：以小块读取内存，处理跨块候选，不再跳过整块大内存；相同密码派生只计算一次；多个 QQ 进程共享有限预算。密钥仍必须通过所选数据库的 HMAC 验证。不会注入 QQ、执行主动提取或保存内存转储。

已经使用 v1 时，直接将 v2 解压覆盖同名修复文件，再运行同一 CMD。

## 使用

1. 保持 QQ 登录。右键任务栏右下角的 Tulpa 托盘图标，选择 **彻底退出**；仅关闭窗口可能仍在后台运行。
2. 打开你平时使用的 `Tulpa.exe` 所在文件夹。将修复 ZIP 中的全部内容解压到这里，合并文件夹。修复后应能同时看到 `Tulpa.exe`、`runtime`、`qq_path_fix` 和 **修复QQ并导入.cmd**。
3. 双击 **修复QQ并导入.cmd**。如果发现多个账号，按窗口提示选择当前登录、希望导入的 QQ。已有来源绑定时只允许导入原账号。
4. 等待窗口依次显示查找、备份、验证、导入、结果。导入阶段显示新增／已有条数和阶段，不需要另点“导入”。消息多时需要更长时间。
5. 导入完成后会自动打开原来的 Tulpa。以后照常双击 `Tulpa.exe`，无需重复运行修复包。

如果实际保存路径不同，把**聊天数据文件夹**拖到 CMD 上运行。路径只保存到本机，不需要发给任何外部服务。

## 数据与中断

- 导入所选 QQ 账号本机可用的全部会话、全部日期，通过现有有界批次入库，不解除每批资源限制。不存在“总共只读 50000 条”的临时限制。
- 使用原有重复消息判断逻辑；再次运行不会把同一条消息重复插入。已有微信消息、模型设置、MCP 连接凭据保留。
- QQ 的消息数据库只读；不移动、不删除、不修改源文件。只在当前 Tulpa 中写入配置、备份、消息、导入缓存和日志。
- 正在运行的 Tulpa 会阻止修复，以免两个进程同时更新。修复和导入期间不要重新启动该安装。
- Ctrl+C 会请求停止，已经入库的批次保留。失败后保持 QQ 登录，再运行修复即可；原有读取器的解密／版本兼容性问题仍可能需要排查。
- 自定义路径会持续用于账号检测、历史导入；导入成功的快照来源也供实时读取使用。**保留原来的实时读取开关**，不会自动开启或关闭 QQ／微信监听。
- 原有 MCP 连接的授权范围不会扩大。若连接被限定为旧会话或日期，新导入内容仍遵守其范围。

## 备份和诊断

每次运行的备份和结果在 `reports/private/qq-source-fix/时间-编号/`：

- `userdata/chats.sqlite3`：修复前聊天库的一致备份，包括已有微信记录；含个人数据，只保留本机。
- `original/`：本次修改前的 QQ 读取器、安装清单、原有路径设置（若存在）。
- `patch.json`、`applied.json`、`result.json`：修改记录、路径校验及最终状态。

导入器的详细日志仍在 `reports/private/data-qq-error.log` 和 `reports/private/imports/`。无需将聊天库或整个备份发送给开发者。突然断电或强制结束后若提示存在升级锁，保留 `.tmp/upgrade.lock` 和这些记录，联系开发者处理。

如果仍未取得密钥，`data-qq-error.log` 中的 `QQ_SCAN` 行记录每个进程实际读取的字节数、候选数、耗时和停止原因：`timeout` 是达到时间预算，`permission_denied` 是实际权限拒绝，`not_found` 是扫描范围内未找到，`verified` 表示验证通过。这些行不含密钥、聊天正文或内存内容。`jieba` 的 `SyntaxWarning` 本身不会阻止导入。

路径设置在 `data/qq-source-root.json`，不写入全局环境变量、QQ 设置或模型配置。恢复旧程序时只恢复所需程序／路径设置，不直接用旧数据库覆盖已经新增的消息。

## 验证边界

自动回归使用真实的 0.5.1 MCP 账号检测、SQLite 入库和分批导入代码，QQ 解密及消息生产使用合成数据。它验证中文自定义路径、重启生效、重复导入、失败续跑、其他数据保留与补丁失败回滚。

v2 的独立测试还验证原有各 HMAC 布局、跨内存块的候选、大内存区、权限错误、时间／字节／候选上限和多进程预算分配。开发机进行了不使用密钥缓存的真实 QQ 只读扫描，约 1.4 秒完成所选数据库的密钥验证；此结果仅代表开发机，不是朋友电脑的兼容性保证。

朋友电脑的源数据库尚未在开发机访问；实际解密和完整导入以朋友运行后的结果为准。此包不声称兼容所有 QQ 版本，不会自动降级 QQ。
