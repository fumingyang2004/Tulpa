# 升级到 0.5.5：保留数据，不重新导入

适用于同一台 Windows 电脑上的 Tulpa 便携版。**下载新版到临时目录，使用新版的升级工具更新原来使用的目录，之后仍打开原目录的 EXE。** 完整版对应完整版、MCP 轻量版对应轻量版。

升级工具保留原目录的聊天、索引、记忆、工作区、附件、读取器密钥缓存、账号选择、实时读取进度、模型和 OneBot 配置、MCP 端口与已有授权。程序文件按发布清单更新，旧清单中退出发布的文件先备份再移除；私人文件不在这个清单里，不会被清空。数据路径没有改变，因此不需要重新导入或修改附件的绝对路径。

## 交给 Codex / DeepSeek Harness

需要能访问本机文件和终端的 Agent；只有远程 MCP 工具权限不能升级本机程序。将以下文字交给它，并填上两个目录：

> 请按新版 Tulpa/doc/UPGRADE.md 帮我从旧版升级到 0.5.5。旧安装目录是「填原目录」，新解压目录是「填新目录」。先检查并另存我修改过的随包人格卡，再核对 build-manifest.json 的版本、edition，并按 GitHub 本版本 SHA256SUMS.txt 校验下载 ZIP。停止本次持续聊天任务，彻底退出这两个目录的 Tulpa，包括托盘服务；不要关闭 QQ、微信或独立 SnowLuma，不要重试未知结果的发送。用新版 runtime/python.exe 运行新版 scripts/upgrade_installation.py --target 原目录，检查结果后加 --apply 执行。不要删除、移动或重新导入旧聊天，不要更换 MCP Token 或扩大连接权限，不要把配置和备份上传。升级后启动原目录的 Tulpa.exe，核对消息数、MCP 连接和实时读取状态；用原客户端凭据重新连接并读一条最新消息。没有我对具体目标的授权不要发送测试消息。保留本机备份，向我报告版本、数据保留校验和哪些监听经过实际验证。

## 自己执行

1. 从 [Releases](https://github.com/fumingyang2004/Tulpa/releases/tag/v0.5.5) 下载与你现用版本类型对应的 ZIP 和 `SHA256SUMS.txt`。用 PowerShell `Get-FileHash 下载的ZIP -Algorithm SHA256` 与文件中的值核对。
2. 完整解压到**新临时目录**，不要在里面启动 Tulpa。找出**原来已经导入聊天、创建授权的安装目录**，确认其中有 `Tulpa.exe`、`build-manifest.json` 和自己的 `data`。不要误选空白包或开发仓库。
3. 在 Codex / DSH 停止持续聊天任务，在 Tulpa 托盘右键选择 **彻底退出**。只关闭窗口可能仍在托盘提供服务。QQ、微信和 SnowLuma 可以保持运行。
4. 例如，新包在 `C:\Tulpa-new\Tulpa`，原来的安装在 `C:\Tulpa`。打开 PowerShell，先执行检查：

```powershell
& 'C:\Tulpa-new\Tulpa\runtime\python.exe' -X utf8 'C:\Tulpa-new\Tulpa\scripts\upgrade_installation.py' --target 'C:\Tulpa'
```

检查不写入文件。结果包括升级版本、程序文件数量、备份所需空间及聊天/授权等记录数量，不输出聊天正文或密钥。提示仍在运行时先彻底退出；不得绕过检查。

5. 检查成功后执行升级：

```powershell
& 'C:\Tulpa-new\Tulpa\runtime\python.exe' -X utf8 'C:\Tulpa-new\Tulpa\scripts\upgrade_installation.py' --target 'C:\Tulpa' --apply
```

程序显示更新进度。`applied: true`、`preserved_state_verified: true` 表示更新及个人数据校验完成；`already_current: true` 表示程序已一致，无需重复更新。

6. 打开 **原目录** `C:\Tulpa\Tulpa.exe`。目录名即使含 `0.5.0`，也可以保留，实际版本以界面及安装清单为准。不要再开新临时目录中的副本，否则会看到一个没有自己数据的新实例。

## 自定义人格如何保留

升级前检查原目录 `chatlocal/prompts/mcp_chat/`。自己新增、与新版随包文件不重名的 `.md` 不在旧发布清单中，升级工具会保留。若你改过随包的 `little_whale.md`、`little_whale_v2.md` 或 `dragon_girl.md`，先在原目录另存为不同文件名（例如 `我的小鲸鱼2号.md`），再运行升级；随包预设属于程序文件，会更新为新版。Agent 代为升级时也应先检查并完成这一步。被替换的旧文件仍保留在升级备份中。

0.5.5 保留已落库的表情笔记、原件与语言学习库。同一机器人 QQ 和群号重新授权后可继续使用原有学习积累，之前明确暂停的选择仍保留；旧连接被撤销后不会复活。学习库的兼容迁移会先生成本地数据库备份，不重新累计原记录。旧表达缺乏群友原话证明时保留为“待复核”，暂不用于回复，详见 [学习与迁移说明](MCP_LANGUAGE_LEARNING.md)。

升级后让 Agent 调用 `list_chat_personas`，选择保留的卡片；已有聊天会话继续使用创建时的人格快照，要用新卡须停止旧会话并重新开启。

## MCP 和实时消息怎么接上

- **MCP**：原端口、启用设置、授权范围、Token 哈希和数据源身份保留。Codex / DSH 使用原来的 MCP URL 和 Token，重新连接；客户端缓存了工具列表时重启客户端或新开任务。无需重建已有连接。检查 `get_data_status` 和最新消息，不能把“工具列表加载成功”等同于监听成功。
- **历史库实时读取**：已启用的 QQ / 微信实时设置和游标保留，打开原目录的 EXE 后按原设置启动。保持对应账号登录，观察“数据与同步”的监听状态及新消息增量；以实际新消息出现为准。之前关闭的监听不会擅自打开。新机器、换账号、客户端缓存变化导致密钥失效时，仍需在界面核对账号并刷新。
- **持续群聊实时事件**：走独立的 SnowLuma OneBot 正向 WebSocket，与数据库监听无关。旧版只有 HTTP 的用户，还需按 [MCP 教程](MCP.md#持续群聊snowluma-实时事件) 设置实时事件地址和 Token，并保持 SnowLuma 运行。服务重启会标记接收间断，不承诺补齐离线期间的群消息。
- **新增权限**：旧授权不会自动得到持续群聊、看图、表情发送或收藏权限。要使用这些能力，请在界面按需勾选并创建新连接，再将它的 MCP Token 配入外部客户端。这是主动扩展权限，与保留原连接升级不同。
- **续聊**：升级不能维持外部模型的推理进程。重新连接后调用 `list_chat_sessions` / `get_chat_session`，核对状态和间断，再按用户要求接续。旧的数据库式聊天会话会停止，需要重新开启；已有 OneBot 会话保留状态。主 Harness 不会因此自动水群。

## 备份、失败和回退

工具将被替换的程序和关键私人状态快照保存在**原目录** `reports/private/upgrades/时间编号/`，同时保存 `journal.json`。普通复制失败会自动恢复本次触及的程序文件，不覆盖个人数据。备份含私人配置与数据库，不得上传 GitHub 或发给其他人。

断电或强制结束可能留下 `.tmp/upgrade.lock`，新版启动器会阻止启动。不要直接删锁继续运行：让本机 Agent 读取对应的 `journal.json`，根据 `files` 恢复 `program/` 中的原文件（原本没有的新增文件只按清单移除），完成后再移除锁。不要清空整个目录。如果已经启动过新版并产生了新消息，不要直接把旧数据库备份覆盖回来，以免丢失升级后的记录。保留备份，核对后再处理。

本工具不合并两个已分别使用的数据目录，不自动跨电脑搬家，不切换完整/轻量版本类型，也不支持降级。开发仓库继续先提交源码、再构建干净包；不要将个人目录整体压缩发布。更早版本没有可用安装清单时先备份整个目录，请维护者核对后升级。
