# 表达选择闭环与黑话补漏验收

2026-10-10。开发前基线 `63c07f1ad6465d4fa9ed5404eb10cf1b39f44a7d`，开发分支 `codex/mcp-auto-learning`。本次同步 GitHub 开发源码，不升版本、不构建/覆盖本地运行包、不发布 GitHub Release。原小鲸鱼与小鲸鱼2号人物卡不改动。所有新验收使用临时数据、模拟模型结果和本机模拟 OneBot，不接触真实群聊。

## 本次实现

- 有候选的文字回复先明确选择 0–5 条或选择空列表。顶层 `next_call` 与实际发送检查一致，旧单条发送接口也不能绕过；缺少决定时尚未派发，不计作发送失败后重试。
- 无候选、学习关闭、沉默和纯媒体不增加选择步骤。学习存储异常明确记录不可用，普通授权聊天继续。候选被人工停用后重新检查，不能复用旧选择。
- 计划回执保存参考条目 ID、载荷哈希、准备时间和明确不用的状态，通过 `get_chat_session.recent_turns` 核对。只声称准备了 MCP 工具返回；宿主请求注入、模型实际采用与学习质量均未验证。发送成功/失败/未知仍由原队列回执说明。
- 黑话合并模型提取与本批原文的最近词匹配；默认只检查同账号群最近 50 个自动词条。只从真实他人实时材料取证，每批每词一次命中，重试不累计。沿用 4/8/25/100 三阶段释义检查、人工优先、停用和来源边界，不增加模型调用。
- 借鉴 MaiBot 固定提交的算法机制，自行实现；不复制其 GPLv3 代码或提示词。来源和配置见[功能说明](MCP_LANGUAGE_LEARNING.md)。不借此扩展至助手输出、工具结果、历史库或跨群共享。

## 可复现的新增验收

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_language_usage.py
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_jargon_matching.py
```

`check_mcp_language_usage.py` 经过真实 MCP HTTP、工具发现和本机 HTTP/WS 适配器。模拟库从 9 条到 10 条，验证候选门槛；直接发送被拦，明确空选择后成功；并发相同选择幂等，改变已定选择拒绝。核对返回的选定内容与持久计划回执，无原话进入附加诊断。另验证人工停用、暂停、存储错误、沉默、纯 reaction、混合计划仅 reaction、过期输入、停止及重启。一次完整执行向本机模拟服务发送 7 条文字、添加/撤销各 1 次 reaction；真实 QQ 写入为 0，真实模型调用为 0。

`check_mcp_jargon_matching.py` 用假时钟让第一次提取发现一个词，后三批包含该词但模型漏提，仍逐批累计到 4；模拟完成带上下文、仅词本身和比较三个阶段后才进入参考。覆盖重复词、并发重复提交、提取失败、重启/新授权、旧 lease、其他账号/群、自身消息、禁用/人工释义，以及缓存上限和关闭补漏。用 70 个已知词验证只匹配最近 50 个；100 次 50 词 × 20 条消息的匹配约 24 毫秒（本机小样本），额外模型/网络调用均为 0。

新增检查已接入 Windows CI 与未来打包门禁；本次未运行打包命令，不能称为新 EXE 验收。两项脚本也支持 `--package <目录>`，供将来使用包内运行时核对。

## 回归与边界

学习存储、学习 MCP 集成、自动学习、群友语言证据、人物加载、聊天 Planner/Replyer、普通 MCP、写权限、持续聊天、媒体与持久表情库、原生 @/引用、reaction、下载和桌面配置回归通过。实际 Edge 加载当前 MCP 界面并使用 API fixtures，验证连接管理、独立持续聊天面板、学习记录和错误恢复；没有修改界面布局。源码发布扫描通过，并检查了此次一并同步的 9 个既有提交中 58 个变更文件版本，未发现该检查器识别的凭证或私人文件；此扫描不等于穷尽所有敏感信息。

聊天三段连续输入用例首次与其他集成测试并行运行时失败，单独重跑通过；未为此改动聊天静默参数或生产算法。新用例开发过程中修正了测试客户端对 `context.messages` 和停止后错误结构的假设，并改从模拟 WS 接收真实格式的引用目标；没有放松原生引用校验。

工程通过不能证明回复更自然、模型更常选择表达或黑话释义更准确。顺序外部 Agent 的无上下文阶段仍标 `degraded`，没有新增模型服务，也不声称获得独立核验。每批重复说一个词不会刷出多个命中；匹配补漏本身不推断含义。

## 更新与回退

仅同步源码。使用开发源码的服务重启后，外部 Agent 重新连接 MCP 并新开群聊会话即可取得新通用提示；无需修改人物卡、重新导入数据或调整 grant。现有安装版继续运行原代码，待另行打包/覆盖后才有这些变化。

学习库只新增查询索引，原表和计数不搬迁；参考诊断作为既有计划 JSON 的附加字段保存，沿用普通结束计划最近 200 条的保留边界。回退源码可从基线另建分支，不用 reset 或删除数据。若手动添加了 `jargon_cache_terms`，回退旧程序前移除这个新配置项；默认无配置文件者无需操作。不要用旧数据库覆盖后续积累。
