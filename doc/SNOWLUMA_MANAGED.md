# 选择本地 SnowLuma，自动配置 QQ

Tulpa 使用你自行下载并解压的 SnowLuma。它不下载、安装、复制或附带 SnowLuma 服务组件，也不再提供“等待上游授权”的下载部署预览入口。第三方组件的使用仍须遵循其[官方协议](https://github.com/SnowLuma/SnowLuma/blob/v1.14.22/EULA.md)；Tulpa 的 MIT 许可不替代上游许可。

## 第一次使用

1. 从 [SnowLuma 官方 v1.14.22 页面](https://github.com/SnowLuma/SnowLuma/releases/tag/v1.14.22)自行下载 **Windows x64 完整版**（带 Node.js，文件名没有 lite），完整解压到自己选择的目录。
2. 打开并登录 QQ，再打开 Tulpa。新解压的 SnowLuma **无需先运行 launcher.bat 或设置管理密码**。
3. 在“连接外部 Agent → 准备资料 → 连接 QQ”输入或选择 SnowLuma 文件夹。要选包含 `index.mjs`、`node.exe`、`package.json` 的目录，不是 QQ 目录或 `config` 子目录。
4. 查看协议，主动勾选 **同意 SnowLuma 使用细则，并自动配置和连接 QQ**，点击 **载入并配置**。检查文件、识别已有连接、检测并保存会连续完成，无需先点击另一个“载入”。这与“OneBot 与后台服务”是同一套设置，切换入口会保留当前路径和进度，不需要重复操作；多个账号或节点时才会要求选择。
5. Tulpa 备份原配置，原地初始化所选运行包，生成管理密码及分别独立的 HTTP/WS Token，选择空闲本机端口，然后核对账号和实时事件。只有一个 QQ 进程时自动连接；多个进程时在 Tulpa 选择目标。如果尚未登录，在 QQ 完成必要扫码即可。
6. 显示“QQ 已就绪”后，在外部 Agent 中使用原有 MCP 连接。无需填写模型 Key、端口、Token 或 SnowLuma 管理密码。

MCP 服务启用与 QQ 就绪是两回事；QQ 尚未就绪时，已有授权内的历史查询仍可使用。配置不会扩大 MCP 的发送、群管理、收藏等权限。

## 已经用过 SnowLuma

同样选择其目录并确认。若已有一个明确的账号和一组可用 HTTP/WS 节点，会自动核对并导入；多账号或多节点时显示选择列表，不猜测目标。已有管理密码、节点及正在运行的外部进程保持不变。

这条导入路径支持已核对的 v1.14.19–v1.14.22；自动首次初始化只支持 v1.14.22 完整版。若旧实例已设置管理密码却尚无可用 OneBot 节点，不能把它当新目录重置；可保留它，另选全新解压的完整包。已有接入服务或残留 Hook 与新服务冲突时，先自行退出旧服务并重开 QQ，或直接导入旧连接。Tulpa 不会擅自终止用户 QQ。

## 取消、重试、重新打开

- 初始化中可取消，迟到结果不会继续启动服务。原运行文件不会被删除。
- 可恢复错误提供“重试”；错误版本、文件变化、协议变化需要重新核对。没有自动换号、轮试密码或重置旧密码。
- Tulpa 重新打开后，可恢复自己启动过的同一文件夹、账号和凭据。QQ PID 变化会重新确认进程；多进程仍需选择。账号与已有资料或授权不一致会停止接入。
- “撤销自动配置授权”终止本连接并关闭 Tulpa 自己启动的 SnowLuma，保留 QQ、聊天、人物卡和学习库。由用户独立启动、仅导入连接的服务不会被关闭。
- 停止后需要改用外部连接，可明确导入或保存高级设置。未重新选择之前，不会悄悄退回另一套 Token。

## 配置、备份和恢复位置

运行文件始终留在所选 SnowLuma 目录，未复制到 Tulpa。其 `config/` 保存上游自身配置以及 `tulpa-owner.json` 归属标识，限定一个 Tulpa 管理，避免两份程序互改。

Tulpa 的 `data/snowluma-managed/` 保存授权、文件指纹、账号/进程绑定及当前用户 DPAPI 加密凭据；`local-config-backup/<实例>/` 保存首次修改前的配置及哈希清单。SnowLuma 运行所需 Token 在其配置内仍为明文，目录限制当前用户和 SYSTEM 访问，不代表管理员或同一用户无法读取。不要公开分享这些目录。

恢复原配置前，先从托盘退出对应 Tulpa，确认其启动的 SnowLuma 已停止，保留新配置副本，再按备份清单恢复原有文件；不要删除用户 QQ 登录或聊天数据。程序覆盖的备份位置由本次交付记录列出，回退程序不应覆盖更新后学习库。

## 实际能力边界

新入口是真实可执行的本地配置路径，不设全局离线开关。开发验证采用隔离运行文件、模拟管理端和 loopback HTTP/WS，未在未经用户勾选的真实 SnowLuma 上初始化密码或执行 QQ 加载。详细分类见[验证记录](SNOWLUMA_MANAGED_VALIDATION.md)。

官方 v1.14.22 即使关闭自动加载，也可能采用已存在的 Hook 管道。Tulpa 在启动/选择/执行时拒绝其他已存在的 Hook，并核对固定账号；动态并发外部服务的底层竞态仍需真实验证，不能承诺上游绝不会短暂接触其他管道。避免同时启动两套接管同一 QQ 的服务。
