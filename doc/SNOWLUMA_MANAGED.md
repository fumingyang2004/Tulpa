# SnowLuma 托管接入预览

本次适配基于官方 **v1.14.22 / 87527cb7641a5a42f8f0efb73cb066102e004dee**。这是离线验证版，**还不能自动部署真实 SnowLuma**。[官方 EULA 第 5.4 条](https://github.com/SnowLuma/SnowLuma/blob/v1.14.22/EULA.md)要求事先取得自动化部署书面授权，目前尚未取得；用户勾选使用协议不等于取得这项许可。程序入口保持关闭，测试只注入内存中的模拟适配器。

## 预期使用流程

1. 打开 Tulpa，进入 **连接外部 Agent → 准备资料 → 自动连接 QQ**。完整版的模型与连接窗口也提供同一入口。
2. 查看展开的官方条款链接、版本、内容哈希及配置范围，主动勾选“同意 SnowLuma 使用细则，并自动配置和连接 QQ”。默认不勾选；条款或范围变化后需要重新同意。
3. 程序下载固定官方完整包，校验大小和 SHA256，安全解压，后台启动独立托管实例，再走官方登录及协议确认接口。管理密码、HTTP Token、WS Token分别随机生成，不需要手抄。
4. 在 Tulpa 内选择 QQ 进程。无法确认账号时显示“账号待验证”；未打开或未登录 QQ 时，只需打开客户端、完成必要扫码。不会按昵称猜账号或给全部 QQ 注入。
5. 管理认证、OneBot 登录账号、WS 生命周期或心跳一致后才显示 **QQ 已就绪**。重新打开 Tulpa 只恢复原账号；QQ 进程变化需要重新选择，账号不一致会停止相关工具。

以上是已实现的离线流程，**第 2–5 步真实 PC 首次运行尚未验收**。当前页面显示“等待上游授权”，按钮不能开启；无需反复保存或重填配置。已有外部服务使用 **已有 OneBot / 高级连接 → 已有 SnowLuma** 导入，见[教程](SNOWLUMA_SETUP.md)。管理外部服务不在本预览的托管权限内。

## 取消、重试与恢复

- 接入中可取消：使在途结果失效；晚到的下载不能接着启动。临时下载可留作下次校验续传。
- 网络失败可重试；不换源、不跳过哈希。损坏包隔离为 `.rejected-*`，下次明确重试重新下载。
- 撤销托管授权：停止相关 QQ 会话与本实例，保留 QQ 客户端、聊天、人物卡和学习库。撤销后旧缓存客户端无法继续使用凭据；不暗中切回其他账号。
- 需要改用外部服务时，先撤销托管，再明确导入或保存外部连接。
- 升级不会静默追随 latest。当前只接受固定 v1.14.22；不同包或已安装文件变化会拒绝启动。跨 SnowLuma 版本升级、自动迁移与一键降级尚未实现。
- 恢复程序：先从托盘彻底退出 Tulpa，保留更新后产生的用户数据，再用升级备份中的 `program/` 文件恢复此次被改的程序；新增程序文件依升级 journal 逐项处理。不要拿旧 `data/` 覆盖新学习记录。完整备份可恢复整个旧目录，但应恢复到独立目录并只运行一份。

## 保护边界

托管数据只在本安装目录 `data/snowluma-managed/`，普通状态文件记录实例、版本、来源、进程身份、端口和授权时间；`credentials.dpapi` 使用 Windows 当前用户 DPAPI。上游自身 OneBot 配置必须含明文 Token，存于限制为当前用户及 SYSTEM 的目录；同一用户或管理员仍可能读取，不是绝对保密。不可公开打包这个目录。

管理、HTTP 和 WS 仅监听 loopback，不开防火墙，不创建开机启动项。新接入不会给 MCP grant 增加发送、管理、收藏等权限，也不会创建模型服务。QQ 未就绪不妨碍授权范围内的历史查询。

v1.14.22 的 `hookAutoLoad=false` 不阻止它连接已有 Hook 管道。因此，本实现启动前发现已有 Hook 就拒绝新建实例；运行时发现其他 QQ Hook 也会暂停。**并发启动外部实例的底层瞬时竞态尚未消除，不能承诺上游绝不会短暂接触其他管道**，真实开放前需要验证或上游提供进程范围控制。不得同时运行两套接管同一 QQ 的服务。

本包不附带 SnowLuma 二进制，没有改写其源码或绕过协议门禁。完整验收分类见[验证记录](SNOWLUMA_MANAGED_VALIDATION.md)。
