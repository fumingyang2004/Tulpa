# 持续水群自动学习与界面修复

2026-10-10，本地测试版。没有 push、版本升级或 GitHub Release 操作。本轮未调用真实模型、未发送真实 QQ 消息；工程验收使用合成材料、模拟模型和真实本机 HTTP/WS/MCP 路由，不能由此证明学习质量提升。

## 使用变化

正常开始持续聊天就会观察当前账号、当前群的实时他人消息。silence 只表示本轮不发话，循环继续。服务端检查材料和时间，通过原等待接口通知可领取阶段；每个阶段结束后必须先回到等待，再决定接话或继续学习。用户无须复制学习指令、手动领取或打开第二个质量开关。

账号群卡区分聊天状态、学习状态、整库积累和本次运行。表达不足10条显示进度门槛；黑话区分已掌握和待观察。暂停、预算及技术详情放在高级设置。数据每3秒刷新，错误保留当前内容并提示重试；历史会话折叠，不合并或误停仍活跃的会话。

学习库和启用偏好按 `qq + 机器人账号 + 群号` 保留。新连接须通过当前授权和来源核验；旧撤销连接不可复活。原聊天多会话能力保留；一个学习连接仍绑定一个群上下文，其他群的学习使用独立连接和 Agent 对话。

自动循环样本：10条启动材料，学习期间追加1条新消息；2个成功的模拟模型阶段，最终3条自检表达、1个未确认用语。时钟到期后的就绪返回约126–155毫秒；配置1秒等待的空队列、预算、lease和冷却场景约1.1–1.5秒返回，均不是立即返回零任务。默认工具续接使用180秒有界长等待，空闲时约每分钟0.33次调用；服务端0.5秒本地时钟不调用模型。结果是小样本工程测量，不是所有电脑的吞吐保证。

并发测试发现“模型阶段中已有一次wait”不能代替阶段完成后的安全边界，已在提交时重新设置回到等待的门槛。迁移测试还修复了Windows上的SQLite备份连接未及时关闭问题。旧的紧时序用例改用明确的600毫秒合成收集窗口，避免150毫秒窗口与机器/数据库延迟竞争；实际聊天默认静默窗口未改。

node scripts\check_mcp_ui.cjs

## 迁移、回滚与人工体验

开发前本地检查点为 `944d9287bbd2968040ea33dda294e0377f4ee35d`，分支 `codex/mcp-auto-learning`。最终本地提交见交付信息及实际包 `build-manifest.json` 的 `local_update.source_commit`。

更新前备份程序、资源、配置、授权库和学习库。迁移只追加表和字段，原表达/黑话/命中表不搬迁、不相加；同账号群有明确关闭时保守保留关闭。已落库条目、人工修订和停用状态不变；未完成任务取消，不把旧原文或旧模型上下文作为新会话。

实际安装目录和私有备份路径在交付信息中核实记录；安装目录名和原版本标识不自动改动。回滚先从托盘退出，恢复备份的本次程序与资源，保留最新配置、人物和SQLite；旧版能读取原知识表，但不认识新增的按群偏好/预算。不要自动恢复旧库，否则会丢失后来积累；数据级回滚须另备份当前库后明确选择。

人工体验只需：

1. 重启Tulpa，在DSH等宿主重新连接MCP，照平时要求小鲸鱼2号在已授权群持续聊天，或先在界面开始再让Agent接续。
2. 保持潜水，出现至少10条新的他人文本并满30秒后，检查学习状态、记录和完成时间；不需要再发第11条来触发。
3. 停止后重新开始同账号同群，确认库计数保留而本次运行计数重置。暂停学习再重开，仍应关闭；高级设置可恢复。
4. 确认少于10条表达没有用于聊天、候选用语没有被当作已掌握。人工停用或修订后重开仍保留。
5. 退出宿主后应显示等待Agent；换账号/群用新的连接及宿主对话，不能显示旧分区学习库。无须修改人物卡或新增模型配置。

## 尚未证明的部分

- 本轮没有在真实DSH模型上重复评估自动循环遵循率和语言学习质量。此前少量真实模型结果属于[旧学习实现的单独试验](MCP_LANGUAGE_LEARNING_VALIDATION.md)，不算本轮自主循环验证。
- MCP不能启动已退出的宿主、清除远端模型记忆或抢断正在生成的模型调用。接话阻塞边界是一阶段模型调用；120秒lease只限制结果有效期，不能保证宿主一定在120秒内返回。
- 顺序自检仍标记 `degraded`，并非独立核验。没有新增embedding或其他模型服务，没有人物画像/历史挖掘/模型训练。窗口仍为40条缓冲、最多20条批次；长期无Agent时可能丢弃最旧观察，不回填历史。
- 记录页显示最近更新的30条/类，整库统计包含全部记录；本轮实际既有库未超过此显示范围。
