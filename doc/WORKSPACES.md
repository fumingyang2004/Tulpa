# 工作区

工作区围绕一个目标持续调查、整理资料并维护可下载的成果。它复用普通聊天的 Harness、检索、媒体理解和证据体系。

## 使用流程

1. 侧栏新建工作区，填写希望完成的事情，设置允许访问的平台、会话和日期。可选已有消息、文件或证据集合为起点。
2. 在 Agent 对话中交任务。侧边资源树提供当前状态、成果、资料、证据、笔记及历史版本。
3. 查看任务取得的证据和拟议改动，确认后应用。后续任务继续修改同一份成果。
4. 预览、编辑、下载 Markdown / CSV；查看差异或恢复旧版本。

普通提问只读，不因模型回答自动修改正式状态。整理任务、用户补充、手工编辑和自动维护都先形成提案；用户确认后才应用并生成版本。待确认事项代表信息缺口，不是自动待办。

## 数据与权限

资料层保存引用、来源和关联理由，不复制整库。导入共享证据集合不会静默修改原集合。已收录资料是优先检索范围，不能扩大允许搜查的边界。

资料可确认、待确认或排除。排除决定持续保留，不因下一次扫描自动复活。范围缩小后，旧任务、旧笔记、成果历史和 SQL 不能成为越权通道。

成果、草稿和版本位于本地 SQLite。程序生成下载字节，没有 Agent 任意路径写入或开放 Shell。应用时检查基础版本与来源指纹，旧任务不能覆盖手工新编辑。回退仅改变工作区产物，不修改聊天原文，也不删除审计历史。

## 变化与维护

`local_changes.seq` 是本地持久递增序列，与相应数据写入同事务提交。覆盖消息增删改、媒体恢复、旧语音转写完成、文件来源 / 解析变化及已同步群资料。无有效变化的重复写入不制造事件，读资料和写笔记不触发自身循环。

进度区分数据已进入本地、候选已处理和修改已应用。只有候选决定可靠保存后才推进，待审批提案不算已更新正式成果。失败、停止和预算耗尽保留可继续的任务与草稿。

默认只廉价发现候选，由用户点击整理或发任务后分析。可显式开启每天、每周或自定义周期的维护，选择范围与预算；没有候选时不调用模型，有候选也只提出建议。

支持指定日期补查和新增范围补查。变化序列出现缺口时要求受控恢复，不宣称完整接续。关键词未命中不等于确定无关，客户端尚未导入的资料也不能被变化流发现。

## 主要表与工具

`workspaces` 保存目标与范围；`workspace_materials` / `workspace_candidates` 保存资料决定和候选；`workspace_tasks` 保存任务；`workspace_outputs` / `workspace_versions` 保存成果及历史；`workspace_proposals` 保存提案；`workspace_audit` 保留审计。

额外工具为 `workspace_read`、`workspace_material`、`workspace_draft`。模型没有批准、应用或回退工具。来源仍区分原始消息、文件、识别 / 转写结果、统计和用户补充。

关联关注卡只保留关联，不复制其调度。删除工作区需确认，不连带删除原始数据、共享集合或独立关注卡。
