# 数据导入与诊断

在 **数据与同步** 中分别选择 QQ / 微信、会话、起止日期和条数。点击读取才会访问客户端；打开设置不会自动重新导入。

## 大范围读取

- 勾选“读取所选日期范围内全部消息”后，一次点击由程序内部自动分批处理，不以累计 50,000 条作为整轮截止。
- 不勾选时保留每会话数量限制。日期先筛选，再应用该数量限制。
- 显示当前阶段、活动进度条、扫描 / 新增 / 已有 / 跳过数量、批次、耗时与诊断编号；总量未知时不显示猜测的百分比。
- 停止或失败保留已提交批次。使用相同范围重试时核对进度并去重，未完成的源扫描可能重新读取。
- 内存、磁盘、身份冲突及同步一致性检查仍有效，不能保证恢复客户端本身没有保存的记录。

JSON / JSONL 文件导入支持项目统一格式及部分常见导出格式。文件导入只读取文件已有内容，单文件上限 100 MB，不会补读 QQ / 微信。

## 图片与表情

读取表情需显式启用。若旧消息媒体缺失，可使用“刷新媒体和表情包”，指定平台、会话和日期重新尝试本机恢复。附件未下载、已过期或定位信息不足时仍可能不可用。

历史读取、实时监听、定时数据刷新和关注卡是独立设置；一次历史导入的勾选不等于实时监听开关或 Agent 搜索授权。

## 排障

先确认客户端已登录、账号一致、两者进程权限相容，并保留错误码和诊断编号。微信只缺联系人库密钥时，可先打开通讯录或联系人资料，保持客户端运行再重试；这不能保证解决所有密钥问题。

本机诊断位于 `reports/private/`，实时摘要位于其 `live/` 子目录。优先使用模型设置中的“导出运行诊断”或 `Tulpa.Support.exe`。不要把完整数据库、密钥缓存、聊天导出、`.env` 或未经检查的日志提交到公开 Issue。

如果 QQ 的“本机账号”始终为空，可使用独立的 [QQ 账号识别诊断](QQ_ACCOUNT_DIAGNOSTICS.md)。它在受影响安装包内复现目录发现与账号列表生成，分别记录阶段、目录布局和错误，不需要读取或解密聊天数据库。

已确认聊天数据使用自定义路径、但 0.5.1 未检测到时，可使用 [QQ 自定义目录临时修复包](QQ_PATH_FIX.md)。它保存当前安装的来源路径，验证账号后调用现有分批流程导入，保留原有 Tulpa 数据及 QQ 源文件。

界面的范围删除仅作用于 Tulpa 的导入数据，不修改原客户端。历史答案、原导出、备份与私人报告并不因此全部擦除；不要将该操作视为完整隐私擦除。
