# 将 SnowLuma 连接到 Tulpa

本文介绍Tulpa 0.5.3 的 **选择 SnowLuma 文件夹 → 选择账号和节点 → 导入、检测并保存** 流程。完整版与 MCP 轻量版使用同一份连接；只接外部 Agent 时不需要填写模型 API Key。已发布版本若还没有文件夹导入入口，可使用本文的[手动配置方法](#高级设置手动配置连接)。

自动导入的配置格式已按 SnowLuma **v1.14.19 / v1.14.20** 核对。其他版本仍可手动连接；格式没有核对时不会猜测端口或尝试其他账号。

## 1. 自行下载并解压 SnowLuma

1. 打开 [SnowLuma 官方 Releases](https://github.com/SnowLuma/SnowLuma/releases)，阅读该版本的说明，下载适合 Windows x64 的运行包。配置格式核对所用版本为 [v1.14.20](https://github.com/SnowLuma/SnowLuma/releases/tag/v1.14.20)。
2. 在资源管理器中右键 ZIP，选择 **全部解压缩**。不要直接在压缩包内运行。
3. 记住包含 `launcher.bat`、`index.mjs`、`package.json` 的文件夹位置。稍后在 Tulpa 中选择这个文件夹，不是 QQ 安装目录，也不是单独的 `config` 子目录。

Tulpa 不下载、安装或修改 SnowLuma，不附带便携 QQ，也不会代你接受协议或设置管理密码。

## 2. 在 SnowLuma 中完成首次设置并加载 QQ

1. 打开并登录你要使用的 QQ。
2. 在解压后的 SnowLuma 文件夹启动 `launcher.bat`。若提示缺少 Node.js 或版本不符，按该版 SnowLuma 的实际启动提示处理后重试。
3. 使用启动窗口显示的 **WebUI / 管理页面地址** 打开控制台。不要凭记忆填写某个端口。
4. 首次运行时，在 SnowLuma 自己的页面阅读并决定是否接受协议，按向导设置管理密码。管理页面密码不是 OneBot 节点 Token。
5. 在进程 / 账号页面按 SnowLuma 提示登录、加载 QQ，确认出现你的账号。再到节点配置中选择这个账号，查看它的 OneBot 节点。

如果节点配置暂时没有账号，但进程页面已显示 QQ，请先检查 SnowLuma 自己的加载 / 连接状态。只有发现进程或探测到账号，不足以证明账号节点已经生成并运行。Tulpa 会明确提示“未找到已生成的账号配置”，不会据此断言你没有登录 QQ。

## 3. 确认账号下有可用节点

在 SnowLuma 中选择要接入的 **QQ 账号**，检查以下节点；缺少时由你在 SnowLuma 中创建并保存：

| 节点 | 用途 | 需要核对 |
| --- | --- | --- |
| HTTP 服务 / HTTP API | 查询当前群资料、下载群文件、执行已授权的发送与管理 | 已启用；host、port、path 和这个节点自己的授权 Token |
| 正向 WebSocket 服务 | 持续群聊直接接收 QQ 实时事件 | 已启用；角色为 **Event** 或 **Universal**；这个节点自己的 host、port、path 和 Token |

同机使用时，节点可监听 `127.0.0.1`。两个独立服务通常需要不同端口；使用你实际配置的空闲端口，不要求固定为 3000 / 3001。若 HTTP 节点明确启用了同端口 WebSocket，Tulpa 也会将它列为一个可选事件节点。

**HTTP 和 WS 的 Token 可以不同。** 自动导入会分别读取所选节点的 Token，无需手动复制。反向 WS 客户端和只提供 API 的 WS 节点不能作为实时事件入口。

只有 HTTP 时也能使用相应 QQ 扩展；持续群聊需要事件节点。不要为此重新生成已有其他客户端正在使用的 Token。

## 4. 在 Tulpa 中选择文件夹、账号和节点

1. 完整版打开 **模型与连接 → QQ 扩展 / OneBot**；轻量版打开侧栏 **OneBot 设置**。
2. 点击 **选择文件夹**，选中第 1 步的 SnowLuma 解压目录。浏览器测试页面中可以直接粘贴完整路径，再点 **识别账号与节点**。
3. 查看识别出的 QQ 账号。只有一个账号时会显示它；多个账号时必须明确选择，不会轮流尝试其他账号。
4. 选择 **HTTP 服务节点** 和 **实时事件节点**。同类有多个节点时需明确选择；禁用或不支持的节点会显示原因，不能导入。
5. 核对下方预览的账号和两个地址。如果只需要 HTTP，可明确选择 **仅 HTTP（关闭 Tulpa 中的事件连接）**；保存后原有实时事件地址会被清空，持续群聊暂不可用。

到这一步只是识别与预览，Tulpa 的已有连接没有改变。取消文件夹选择、关闭窗口或识别失败，都不会覆盖原配置。

## 5. 导入、检测并保存

点击 **导入、检测并保存到 Tulpa**。这一步会：

1. 使用所选 HTTP 节点调用 `get_login_info`，核对实际 QQ 账号与所选配置账号是否一致。
2. 核对该账号与 Tulpa 已导入的 QQ 来源及已有 MCP 账号授权是否一致。
3. 如果选择了事件节点，用它自己的 Token 建立 WS 连接，并从生命周期 / 心跳事件核对同一 QQ 账号。端口开放或 WS 握手成功本身不等于检测通过。
4. 所选连接通过后，将地址和凭据保存到 **Tulpa 自己的本机配置**。检测失败、配置在过程中变化，或账号不符时保留原连接。

看到“HTTP 与 WS 均已核对同一 QQ 账号，已保存”后，可回到外部 Agent 重新连接 MCP。发送、群管理与持续群聊仍需你在对应 MCP 连接上授予权限；导入连接不会新增或扩大授权。

检测只查询登录与连接状态，不发送 QQ 消息、不查询聊天正文、不更改群权限。Token 不显示在预览、API 响应或日志里。SnowLuma 的节点、Token、密码和其他客户端配置均不修改。

## 高级设置：手动配置连接

导入区域下方有默认折叠的 **高级设置：手动配置连接**。使用其他 OneBot 实现，或自动识别遇到不支持的格式时，可展开填写：

| Tulpa 字段 | 填什么 |
| --- | --- |
| 本机 OneBot 地址 | 所选 HTTP 服务的完整基础地址，例如 `http://127.0.0.1:43120/qq-api`。保留节点 path，不加 `/get_login_info` |
| 访问 Token | **HTTP 节点**的授权 Token，不是 SnowLuma 管理页面密码 |
| 实时事件地址 | 所选正向 WS 服务的完整地址，例如 `ws://127.0.0.1:43121/qq-events` |
| 事件 Token | **WS 节点**自己的授权 Token，不要假设它与 HTTP 相同 |

以上地址只是格式示例，不能直接当作你电脑上的实际配置。主机、端口、路径应从自己选中的节点取得。

点击 **保存并检测** 保存你明确填写的手动配置。手动表单的空 Token 表示保留已存值；修改 Token 时要填入新的实际值。还可以点击 **检测已保存的连接 / 检测连接** 单独检查当前配置。模型 API 地址、API Key 和模型名称不影响 OneBot 独立保存。

## 失败提示怎么处理

| 提示 | 下一步 |
| --- | --- |
| 文件夹不存在、选错目录或缺少文件 | 完整解压，再选择含 `package.json`、`index.mjs` 的 SnowLuma 根文件夹；不要选 `config` 子目录 |
| 没有生成账号配置 | 手动启动 SnowLuma，完成首次设置并登录、加载 QQ，再回 Tulpa 重新检测。仅有全局 `onebot.json` 不会被当作某个账号的配置 |
| JSON 损坏、格式 / 版本不支持 | 在 SnowLuma 检查配置，或展开 Tulpa 的手动连接入口；Tulpa 不会修复、重置或覆盖原文件 |
| 节点禁用 / 没有可用 HTTP 节点 | 在 SnowLuma 对应账号下自行启用或创建本机 HTTP 服务，保存后重新识别 |
| HTTP 认证被拒绝 | 核对所选 HTTP 节点自己的 Token；不要混用管理密码、WS Token、MCP Token 或模型 Key |
| HTTP 无法连接、超时或接口路径不存在 | 核对该节点是否运行以及实际 host / port / path；不要用管理页面地址代替 OneBot 地址 |
| HTTP 成功，WS 认证或握手失败 | 核对所选事件节点的独立 Token、端口、path 和角色；自动导入不会保存失败的一半配置。如只需 HTTP，可明确选择仅 HTTP 后再次导入 |
| WS 未返回可核对事件 | 尚未确认事件链路可用；检查 SnowLuma 的账号和节点状态后重试，不能只凭端口开放判断成功 |
| 实际账号不同 / 与来源或授权不符 | 选择相符账号。不要通过轮换 Token 或重建其他人的节点凑成功；其他 QQ 来源需要独立的 Tulpa 数据目录 |
| 识别结果过期、检测期间配置变化 | 重新识别、核对节点后再保存，避免把旧的预览写回 |

## 以后每次使用

打开并登录 QQ，启动 SnowLuma，再打开 Tulpa。三者运行在同一台电脑上。地址和凭据未变时不用再次导入；改了节点、Token 或目录内容后，重新选择并核对即可。

普通本地历史查询不依赖 OneBot。需要持续群聊时，SnowLuma 事件节点和外部 Agent 都要保持运行；配置成功不代表 Agent 永久执行。

## 格式与许可说明

配置读取根据 SnowLuma [v1.14.20 的 OneBot 配置实现](https://github.com/SnowLuma/SnowLuma/blob/v1.14.20/packages/onebot/src/config.ts)及对应发布包核对：读取实际 `onebot_<账号>.json`；`snapshot` 不继承全局节点，其他已支持的布局按节点名称合并。仅读取指定目录内有限数量的配置文件，不扫描整盘，不尝试全局默认账号。

SnowLuma 是独立项目，用户应阅读并遵循其许可证与首次设置协议。Tulpa 不包含 SnowLuma 服务程序；其 [EULA](https://github.com/SnowLuma/SnowLuma/blob/v1.14.20/EULA.md)对第三方分发有单独要求，本功能不改变这些要求。
