# MCP 实时语言学习

本功能只作用于持续 QQ 群聊 MCP。程序保存有限的实时材料，外部 Agent 分阶段提取、审核表达和解释黑话。没有模型训练、人物画像、历史库回填、新 API Key 或后台内置模型。原人物卡不改写。

## 开启与操作

1. 保持 OneBot、Tulpa 和已连接的 Agent 运行。在专用 Agent 对话中正常提出“用小鲸鱼2号在某群持续聊天”，就会同时开始观察与学习。无需另外启用学习、抄学习口令或手动领取阶段。
2. 也可在 Tulpa → 连接外部 Agent → **开始持续水群**中选择已有连接、群和人物。界面显示机器人 QQ 与群号；Agent 随后按平时方式进入同群、同人格，会接续这个会话。点击按钮不会自行启动模型，尚未接续时显示“等待 Agent”。
3. 群卡显示潜水/准备回复/已停止，以及积累中/学习中/等待 Agent/预算暂停/学习关闭。**查看学习记录**查看表达和群内用语；高级设置可暂停当前账号群的学习或调整每小时阶段预算。此前明确暂停的选择会保留，新连接不会解除暂停。
4. 停止后原库保留。原账号原群重新开始并通过当前授权核验即可接续，无需第二开关。换账号或群须新连接、新宿主对话；不要在旧模型上下文中混用不同分区。

通过自检的表达默认进入可用范围；不足 **10 条**时仍不注入聊天，界面显示例如“4/10，继续积累后才用于聊天”。黑话的“待观察”不等于已掌握。提取和自检确实分阶段调用，但顺序宿主可能记得前文，不能称为独立核验或质量保证；高级详情保留 `independence=degraded`。已取消额外的“允许顺序审核结果”开关。

没有活跃宿主或宿主结束任务时，服务器只积累有界材料，显示等待 Agent；不会自行启动模型。升级后重启 Tulpa，并在客户端重新连接 MCP 以刷新工具说明。只需正常开始持续聊天，不需要知道领取工具名称。宿主是否持续遵循循环仍由宿主控制，Tulpa 无法强制一个已退出的 Agent 继续推理。

## 边界和存储

- 服务端从当前已核验 OneBot 连接和聊天授权解析 `qq:机器人账号:group:群号`。模型工具不接收账号或群号参数。
- 开始后学习会将该 MCP grant 固定在这个持续聊天作用域。即使暂停也保留绑定。换群/账号请创建新 MCP 连接，在新的宿主对话中使用；其他普通查询工具的原有授权不变。已存在的多会话不会被合并或误停；同一连接已有多个群时学习会提示需要独立连接，不暗中混用上下文。
- 库和暂停偏好属于平台 + 机器人 QQ + 群，独立于 session/grant。同账号同群的新授权通过现有权限和来源核验后接续；旧撤销连接仍不能访问。换账号或群看不到旧库、计数或诊断。
- MCP 无法清除宿主已经收到的上下文，也无法证明调用者确实新建了对话。本版采取服务端 grant 固定作用域和上下文标识绑定，但**不声称远端模型已遗忘**。用户/宿主仍需建立新上下文，不应混用同一对话中的多个连接。
- `data/mcp-language.sqlite3` 是单独本地 SQLite。库、偏好和预算按账号群保存；观察、lease、宿主上下文绑定和在途任务仍按当前授权、会话、连接代际隔离。原聊天库不读取、不迁移。迁移此文件时，运行中使用 SQLite backup，不能仅复制活动文件而遗漏事务。
- 默认缓冲 40 条、每批最多 20 条、至少 10 条；首次从开始/恢复学习起计时，后续从上次封批起至少 30 秒。收到消息及服务端 0.5 秒时钟都检查封批，不依赖 claim 或第 11 条消息；领取端也重检同一状态。材料被封批后从观察缓冲消费，原始消息 ID + 时间 + 账号群形成有界去重账本，跨 session/grant 重投不会重复计数。
- 20 条一批用于保留短段对话的前后文；40 条缓冲可容纳两批突发输入，同时受字符预算约束。这是首版的有限成本默认值，尚未通过大规模群聊调优。
- 原始证据最多 24 小时、每个授权分区最多 100 个有原文的批次，先触及的边界生效。黑话保存来源引用，需要时从有限批次还原前后各 3 条，不把每个词的上下文重复复制到永久库。清理在访问分区或下次启动时执行；程序关闭期间不会运行清理进程。
- 抽象表达、黑话和去重元数据长期保留。停用、切号、断线均不删除库；删除整个学习库属于另行管理操作。
- 断线、停止、撤权、进程重启均取消未完成任务和待注入候选。迟到结果拒绝；重启恢复的是已完成记录和去重账本，**不自动续跑旧连接的半成品任务**。黑话的新推断也只取当前授权、会话及连接代际的有效实时证据，不把旧原文带入新宿主上下文。

## 调度和实际模型调用

工具：`get_chat_learning`、`claim_chat_learning`、`submit_chat_learning`、`select_chat_expressions`。自动循环使用现有 `wait_chat_messages`：消息 → Planner（允许 silence）→ 确认进度并等待；或 `learning_ready` → 按返回的 `next_call` 领取一个阶段 → 分次模型判断和提交 → 回到等待。服务端阻止连续领取绕过等待边界；`context_id` 可省略，使用本会话稳定绑定。

就绪状态同时核验权限、预算、冷却、lease 和聊天队列；pending 数量不代表可领取。wake 标识由任务、阶段和版本派生，原子 lease 防双领，重复提交幂等。领取后必须回到等待接口才能推进下一阶段；新消息和 reaction 通知优先返回，READY/SENDING 聊天工作优先。不发话也要观察、确认进度和等待，silence 不是停止。

一个表达批次通常需要 **2 次模型调用**：

1. `extract`：3–5 条表达（无可靠材料可空），另附最多 30 个黑话候选。表达必须描述**来源群友实际说话的形式**，同时提供本批 `source_id`、逐字 `evidence_quote`、原文可见的 `surface_form`（可用 `{对象}` 等变量槽位）及 `form_type`。不是把群友的话当刺激，再总结机器人应该怎样回应。
2. `review`：另次调用逐项核对群友表达、原文支持、非应对策略、去除人格仍成立及隐私；理由须指出原话的语言特征。“符合人格”“本轮实际做法”不能作为接受理由。接受的完全相同条目每批计数一次。

程序会验证原话确实属于所引来源，语言模板固定部分在原话中存在，检查项均为明确布尔值，并拦截已知的“保持沉默、不插话、顶回去”等策略型结果。模板支持用词、句式、标点和双关；普通群友说“别太离谱”不因含否定词而被禁止。字面验证和有限规则不能判定所有语义，最终自检仍可能出错，不能宣称已实现独立核验。

此前没有群友语言证据的旧表达原样保留，界面标为“旧记录待复核”，不再进入回复候选；原启停状态及计数不改。后续实时学习遇到有证据的相同条目才会补足证明，**不会自动重读旧群聊或批量把旧记录升级为通过**。新通过的表达仍须达到 10 条才开始提供候选，不另加启用开关。`expression_grounding` 保存来源编号、批次、模板和引文哈希，不长期另存逐字引文；原文仍受既有 24 小时证据期限约束。

提取明确返回空表达列表时没有待审核表达，跳过空审核，节省一次调用；黑话仍仅作为未确认候选积累，不能借此直接获得释义。

黑话新候选 `is_jargon=false`、释义为空。命中批次累计到 **4、8、25、100** 时，另外需要 **3 次模型调用**：带上下文解释 → 仅词本身解释 → 比较。比较须有充分证据且意义不相同时才确认。一次计数跨多个里程碑时只推断当前计数一次；到 100 后结束自动推断。人工释义优先，进行中的自动结果也不能覆盖。

提取和审核工具领取/提交是不同阶段，要求不同 `invocation_id`；这可以阻止误复用调用编号，**不能从服务端证明模型真的推理了两次**。宿主应实际分次调用。本版没有可验证的隔离子模型适配器：即使 `without_context` 的本次材料只有词，顺序对话仍可能看过前文，因此全部自动结果标记为降级。不提供靠一个布尔参数就升级成“独立验证”的通道。

默认每个账号群每小时最多领取 20 个阶段；创建新连接不会重置预算。每阶段最多 2 次尝试，重试至少等待 15 秒，lease 120 秒；每会话一个领取，全局最多三个。预算、lease 占用、重试冷却时 wait 保持等待，默认连续调用使用 180 秒有界长等待；到期返回 idle 后继续 wait，不做零任务忙循环。按默认等待约每分钟 0.33 次空闲调用，服务端本地时钟不产生模型调用。

学习期间出现新消息，在该次模型阶段返回后的安全边界优先接话。程序不能打断外部宿主正在执行的模型调用；120 秒 lease 只使迟到提交失效，不代表能强制取消模型或保证最长 120 秒后回话。实际响应上界取决于宿主超时和生成时间。

READY 回复超过原发送 TTL 后不再阻塞学习领取；发送中的队列仍优先。这里只判断学习调度，不修改原回复队列或消息新鲜度算法。

默认每条材料最多 800 字符、批次 16,000 字符；审核或比较输入上限为该值两倍（含候选/两份释义）。这不是 token 计费估算；状态页报告实际领取次数和序列化材料字符数，不虚构模型账单。

## 回复时使用

- 仍先 `plan_chat_reply`。只匹配该计划关联的已读真实他人文本，不能扩大到未读页或历史库。
- 可用表达不足 10 条不出候选；没有 embedding 配置时按 count 加权、不放回抽样：全库最多5条，计数大于1的高频池至少10条时另取最多5条，合并去重后至多10条。候选固定在该计划，不因轮询反复换样。模型用 `select_chat_expressions` 选择 0–5 条后组织回复，也可全部不选。
- 当前 MCP 没有已有 embedding 服务配置，因此本版实际使用加权路线。存储层有受作用域约束的可选检索器接口并用 fixture 验证最多 50 条；这不代表已经上线向量服务，也不会偷偷调用新的服务。
- 黑话仅用大小写归一后的子串匹配，最多 10 条有释义且确认/人工设置的词。候选、空释义、禁用记录不作为确定知识。
- 人物卡优先，学习只作本轮可选数据。不会修改原小鲸鱼或小鲸鱼2号，不自动复读、不强制发言、不绕过原来的等待、目标、新鲜度、权限和气泡队列。

配置可选放入 `data/mcp-language-policy.json`，修改后重启；默认不需文件：

```json
{"window_messages":20,"buffer_messages":40,"interval_seconds":30,"evidence_seconds":86400,"evidence_batches":100,"message_chars":800,"material_chars":16000,"lease_seconds":120,"hourly_calls":20,"max_attempts":2,"retry_seconds":15}
```

无效配置会停止学习并报错，不能静默降低安全门槛。局部覆盖字段可用；观察门槛 10 条、最低间隔 30 秒、全局并发 3 不允许越过。

## 验收和回滚

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_language_learning.py
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_language_integration.py
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_auto_learning.py
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_expression_evidence.py
.\.venv\Scripts\python.exe -X utf8 scripts\check_mcp_chat_turns.py
$env:PLAYWRIGHT_MODULE = 'C:\Lab0921\.tmp\desktop-qa\node_modules\playwright-core'
node scripts\check_mcp_ui.cjs
```

前四项使用假时钟、合成消息和本机模拟接口；不读取真实历史库、不调用真实模型、不发 QQ 消息。UI 验收使用真实 Edge、实际样式和脚本加接口 fixture。`--package <目录>` 可核验实际打包模块。mock 证明工程边界，不证明语言质量或宿主永远遵循循环。

人工测试：正常开始指定群的持续聊天，让 Agent 潜水；出现至少10条他人实时消息并满30秒后，即使没有后续消息也应开始学习。查看记录页与4/10等门槛；停止再开，条目与人工修改保留，本次运行进度从新会话计起。高级设置暂停后重开仍暂停。宿主退出应显示等待 Agent；不要把队列存在当成学习已完成。

首次升级会在学习库旁创建 `mcp-language.before-auto-*.sqlite3` 一致性备份，然后追加账号群库、运行状态和预算表。表达/黑话原表不搬迁、不重复相加；历史偏好有明确关闭时保守保留关闭，时间取已有记录的最大值，无时间显示“未记录”。迁移标记保证重跑不叠加计数。

首次启用群友语言证据校验会另外备份为 `mcp-language.before-peer-evidence-*.sqlite3`，仅追加证明表。恢复旧程序后，旧程序不会识别“待复核”门槛，可能再次使用原有策略型记录；不建议仅为恢复旧数量而降级。默认保留最新数据库，恢复旧数据库会丢失此后的学习，须先另行备份。

本地更新备份位置和实际运行路径见交付记录。回滚先退出 EXE/托盘，仅恢复备份的程序和资源，保留配置、人格及最新学习库。旧版能读取原知识表，但不会识别新增的账号群偏好和预算，可能回到旧连接设置；重新升级仍使用新偏好。不要自动用旧数据库覆盖新库，否则会丢失升级后积累。确需数据级回滚，先另备份当前库再由用户明确选择旧快照。源码可以从检查点另建分支查看，无须 reset/clean。
